# v0.4.0 — recorded CORD service evidence

This release makes the frozen 2026-10-05 receipt experiment and its CPU checks
available with the current evaluation package. **It is a research artifact, not
deployment approval: both BF16 and AWQ fail the predeclared quality gates.**

## Included

- Fourteen recorded workloads / 3,792 measured requests comparing Qwen3-VL-8B
  BF16 with the existing AWQ export on pinned CORD-v2 receipts. Raw predictions,
  manifests, launch records, NVML samples, immutable script snapshots and an
  evidence hash index are included in the source archive.
- The null-only compressed-tensors metadata adapter, cross-split image-content
  checks and repeated-workload summaries used in the study. Original exported
  weights remain unchanged; non-null metadata is not guessed away.
- CPU checks for archived hashes, request/score consistency, paired intervals,
  memory peaks and timing summaries. Current regression gates and output-file
  protection are retained.
- Five unmodified reviewed receipt images with NAVER CLOVA / CORD attribution
  and CC BY 4.0 terms. Full receipt datasets, model weights and GPU dependencies
  are not included in the release packages.

## What the recorded result says

AWQ reduced the sampled whole-device workload peak from 21.67 to 12.11 GiB
(−44.1%) on one RTX 5090 with a fixed 2 GiB KV cache. Median dev throughput across
three repeats increased 21.7% at concurrency 1 and 12.5% at concurrency 4; the
published study retains repeat values and ranges.

All four field-quality scores remain below the predeclared 95% target for both
models. AWQ introduces two total-amount errors: `377,859 → 377,059` and Total
`16,500 → Cash 50,000`. The total-field paired interval [−3.16, +7.37] percentage
points does not establish loss within the 2-point margin. The quality decision
remains **FAIL** despite the resource savings.

This release performs no new GPU experiment. Single-device sequential execution,
timing variability, possible pretraining contamination and request-level rather
than GPU-tensor fingerprints limit the conclusions. Primary scores compare CORD
parsed-field annotations; a separate post hoc currency-spacing diagnostic does
not alter the original gates.

## Downloads and local verification

- `vlm_precision_lab-0.4.0-py3-none-any.whl`: installable Python package. It does
  not bundle the experiment archive or examples.
- `vlm_precision_lab-0.4.0.tar.gz`: source, tests, example images, documentation
  and the recorded experiment archive.
- `SHA256SUMS`: SHA-256 digests of those two packages.

Download the source archive and `SHA256SUMS` from this release. On macOS/Linux,
use `shasum -a 256 vlm_precision_lab-0.4.0.tar.gz`; on Windows PowerShell, use
`Get-FileHash vlm_precision_lab-0.4.0.tar.gz -Algorithm SHA256`. Compare the result
with its entry in `SHA256SUMS`, then extract the archive.

With Python 3.11+, open the extracted source directory and create a virtual
environment. After activating it:

```sh
python -m pip install '.[test,data]'
python -m pytest -q
python experiments/build_demo.py --output runs/site/index.html --copy-images
```

The CPU suite checks the frozen receipt evidence and the package's other
behaviors. The browser replay contains 300 historical synthetic questions;
it links to the separate receipt study. Neither command reruns model inference.
Verifying the unbundled original receipt-image bytes requires a separate pinned
dataset import, described in the case study.

Local release validation: **69 CPU tests pass**, the standalone wheel installs,
the source distribution passes its bundled suite outside the checkout, and the
recorded 300-question demo rebuilds. The frozen receipt archive is byte-identical
to its original experiment commit. Code is Apache-2.0; model, dataset and
upstream AWQ/Marlin licenses and attribution remain separate.
